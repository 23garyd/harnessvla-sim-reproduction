## 2. Completion attribution (who fires the predicate?)

For each of the 11 harness successes, the states.json entry where
`libero_terminated` first reads true:

| run | predicate fired during | kind |
|---|---|---|
| goal_swap s1 | release | analytic |
| goal_swap s2 | move_to | analytic |
| goal_swap s5 | release | analytic |
| goal_task s1 | release | analytic |
| object_swap s2 | release | analytic |
| object_swap s5 | release | analytic |
| spatial_task s1–s4 | release ×4 | analytic |
| spatial_task s5 | pi0_pick | VLA |

**10 of 11 harness successes complete during an analytic primitive**
(9 release, 1 move_to), 1 during the VLA primitive. The division of
labor the paper claims — VLA as a sparse grasp specialist, planner
finishing the task analytically — is exactly what the artifacts show.
The complement (Day-7 taxonomy): when the harness *fails*, the leading
primary cause is that same analytic release/place geometry (3 of 7
triaged failures). The seam that wins is the seam that loses.

## 3. VLA-invocation profile

| group | vla calls min/med/max | analytic calls | turns |
|---|---|---|---|
| harness success (n=11) | 1 / 1 / 2 | 3 / 7 / 9 | 17 / 21 / 28 |
| harness failure (n=9) | 2 / 3 / 5 | 12 / 21 / 25 | 47 / 60 / 60 |
| direct (n=20, chunk calls) | 22 / 120 / 120 | — | — |

- Sparse-retry claim reproduced: successful harness rollouts invoke pi0
  **once** (median; max 2) against direct's 120-chunk budget (median =
  cap; the min 22 is a direct success terminating early).
- The outcome distributions are cleanly separated with no overlap in
  turns (success ≤ 28, failure ≥ 47): a rollout either converges fast
  or grinds to a budget. Turn count at ~30 is an early-warning signal a
  live operator (or a future watchdog) could use, though under the
  frozen protocol it changes nothing.
- Failures also multiply VLA retries (median 3): consistent with the
  Day-7 chains, where re-grasping after a drop is the dominant sink.

## 4. Hidden-memory ablation result (predeclared; registry v2-hiddenmem)

Predeclaration (before any rollout): H1 = the released TSM's carry_z
ballistic-release rule causes the Object-S regression; prediction
"> 2/5 with releases executed at/below rim height". H0 = memory
net-helpful or neutral (≤ 2/5).

Result — **hidden-memory 5/5** (all raw-verified, per-seed leak
tripwire clean; `artifacts/ablation/ledger.csv`):

| seed | direct | v2 harness (with memory) | v2-hiddenmem | terminal eef z |
|---|---|---|---|---|
| 1 | ✓ | ✗ turn_budget (release z=0.334 bounced out) | **✓ 22 turns** | 0.214 |
| 2 | ✓ | ✓ | **✓ 26 turns** | 0.187 |
| 3 | ✓ | ✗ turn_budget | **✓ 15 turns** | 0.285 |
| 4 | ✗ | ✗ turn_budget | **✓ 18 turns** | 0.219 |
| 5 | ✓ | ✓ | **✓ 19 turns** | 0.180 |

**H1 outcome confirmed**: removing the released memory didn't just
recover the with-memory regression (2/5 → 5/5), it beat direct (4/5) —
including seed 4, which BOTH frozen arms fail. Memory-free runs were
also fast (15–26 turns, 1 pi0 call each) — no exploration penalty on
this cell.

> **CORRECTION (Day-9, 2026-07-28 — mechanism revised).** H1's causal
> story ("the carry-height release rule causes the bounce-outs") was
> falsified by the Day-9 adversarial triage of the s3/s4 with-memory
> retries: the seed-0 reference succeeded from z=0.367, hidden-mem s3
> succeeded at carry height z=0.28 without descending, and depth-map
> ground truth shows the failing releases were **+0.078–0.082 m
> off-center in x — outside the basket footprint** (half-width 0.075),
> while all successful releases were within 0.005 m in x. The memory
> harms this cell via **reference-coordinate anchoring**: the cached
> s0 basket absolute (0.076, 0.231) made both planners select the
> +x-biased perception estimate over the accurate one their own tools
> returned. z is confounded with xy in this table; xy is decisive.
> Full evidence: `day9_case_studies.md` §1–2. The ablation OUTCOME
> (5/5 vs 2/5) is unaffected.

Scope caution for the report: this is ONE cell (5 seeds) chosen
BECAUSE Day-7 triage implicated the memory there; it does not license
"memory hurts" in general — on Spatial-T/Goal-S the with-memory harness
is what produced the 8 rescues, and the paper's swap-cell asymmetry
prediction (memory should matter most where re-grounding is required)
is untested here. It licenses: the released TSM is not uniformly
seed-robust, and its placement rules can invert a strong cell.

### Ablation-integrity findings (methodology, reportable)

Two attempts were invalidated by the tripwire before the clean run:
1. The planner, finding memory/ absent, ran repo-wide `find` hunts and
   READ THE STASH BACK (attempt 1, stash under artifacts/). Naive
   resource-hiding is not a valid ablation technique for agents with
   shell access.
2. After the stash moved to an opaque out-of-repo tar, the HF download
   cache still leaked note FILENAMES via `*.lock`/`*.metadata`
   (attempt 2 seed 4) — strategy-bearing titles like
   `tall_item_first_basket_placement`.
Hardening that held: opaque tar in a 0700 mktemp dir outside the repo,
HF_HUB_OFFLINE=1, per-seed tripwire grep over launcher.log + run.log +
stream for the stash path and note filenames. Quarantines:
`artifacts/ablation/attempt1_condition_violated/`,
`artifacts/ablation/attempt2_seed4_condition_violated/`.
